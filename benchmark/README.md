# Groq Guardrail Model Benchmark

Benchmarks two Groq-hosted guardrail models against the Guardrailer 10k-sample security evaluation corpus:

| Model | Type | Description |
|-------|------|-------------|
| `openai/gpt-oss-safeguard-20b` | Policy-following safety classifier | Interprets custom policies, returns violation decisions with reasoning |
| `meta-llama/llama-prompt-guard-2-86m` | Injection detector | Scores injection probability (0–1) |

## Setup

```bash
# Install dependencies (if not already present)
pip install groq pandas numpy rich tqdm python-dotenv --break-system-packages

# Configure API keys
cp .env.example .env
# Edit .env with your Groq API keys
```

## Execution Modes

### 1. Live Async Pipeline (recommended for smaller runs or testing)

```bash
# Run all models with default concurrency (20)
python benchmark_pipeline.py

# Run specific models
python benchmark_pipeline.py --models openai/gpt-oss-safeguard-20b

# Adjust concurrency
python benchmark_pipeline.py --concurrency 30
```

**Features:**
- Dual API key rotation with round-robin dispatch
- SQLite checkpointing — restarts skip already-evaluated samples
- Exponential backoff with jitter on HTTP 429 rate limits
- Rich terminal progress bar with live stats

### 2. Batch API Pipeline (recommended for full 10k corpus)

```bash
# Full pipeline: prepare → submit → monitor → download
python batch_runner.py run

# Or run individual stages:
python batch_runner.py prepare    # Generate .jsonl payloads
python batch_runner.py submit     # Upload files & submit batch jobs
python batch_runner.py monitor    # Poll status until complete
python batch_runner.py download   # Download results into SQLite
```

**Features:**
- Cost-effective offline evaluation via Groq Batch API
- Automatic file upload and batch job creation
- Status monitoring with configurable poll intervals
- Result download and parsing into the shared SQLite database

## Auto-Resume

Both pipelines use `benchmark_results.db` (SQLite) for checkpointing. On restart, completed `(prompt_id, model_id)` pairs are automatically skipped — no work or API credits are wasted.

To force a full re-run:
```bash
rm benchmark_results.db
```

## Output

### SQLite Database (`benchmark_results.db`)

| Column | Type | Description |
|--------|------|-------------|
| `prompt_id` | TEXT | Row ID from parquet file |
| `model_id` | TEXT | Evaluated model identifier |
| `prompt_text` | TEXT | Raw input string |
| `ground_truth_label` | INT | 1 = malicious, 0 = benign |
| `raw_output` | TEXT | Full model response |
| `parsed_prediction` | INT | 1/0/-1 (malicious/benign/parse error) |
| `latency_ms` | REAL | Response latency in ms |
| `api_key_index` | INT | API key used (0 or 1) |
| `timestamp` | TEXT | UTC ISO timestamp |

### JSON Summary (`results/benchmark_*.json`)

Generated by `benchmark_pipeline.py` with metadata and per-model aggregate stats.

### Raw Batch Outputs (`results/batch_*_raw.jsonl`)

Raw Groq Batch API response files from `batch_runner.py`.

## Analysis

Results are directly compatible with the existing evaluation framework:

```python
import sqlite3
import pandas as pd

conn = sqlite3.connect("benchmark_results.db")
df = pd.read_sql("SELECT * FROM results", conn)

# Filter to a specific model
safeguard = df[df.model_id == "openai/gpt-oss-safeguard-20b"]

# Compute metrics
from sklearn.metrics import balanced_accuracy_score, f1_score, confusion_matrix
y_true = safeguard.ground_truth_label
y_pred = safeguard.parsed_prediction
print(f"Balanced Accuracy: {balanced_accuracy_score(y_true, y_pred):.4f}")
print(f"F1 Score: {f1_score(y_true, y_pred):.4f}")
print(confusion_matrix(y_true, y_pred))
```
